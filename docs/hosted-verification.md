# Hosted revision verification

Verified on Windows with Python 3.12 and the installed Node/Java toolchains:

- 67 backend tests: original content/comparator/scoring/complexity and process-control regressions, schema 1/2 migration preservation, authentication/CSRF/CORS, ownership, five-team queue load, five-versus-four solved fixtures, manual start, real provider-free execution, local startup/bootstrap, optional managed recovery, and the seven new content packages. New tests cover independent randomized oracles, exact generator reproduction, valid maximum-size inputs, arbitrary tree labels, catalog discovery, pinned selections, source history, privacy, and organizer reviews.
- Four original practice browser scenarios, covering the three Hard challenge flows, the ten-problem catalog, reviews, old attempts, drafts, responsive editing, and unavailable backend behavior.
- Two contest browser scenarios using separate organizer/team contexts and real local Python execution. The original scenario retains its pinned three-problem selection and covers publication/waiting, manual start, confirmation cancellation, lost-response retry after editing, private history, session reset/rejoin, draft isolation/recovery, organizer reviews, and ended read-only access. The new scenario selects all seven introductory problems, runs their samples, confirms runs create no official history, records Add Two Numbers, and saves/reloads organizer quality and complexity feedback beside the saved source.
- Nine formatter example programs: Python/JavaScript/Java each still pass exactly 1, 3, or all 65 official cases (and 1, 3, or 6 visible samples).
- Both hard-challenge reference suites pass in Python, JavaScript, and Java within the provisional five-second per-case limits. Local C++ checks were skipped because `g++` is not installed; managed C++ remains subject to live provider verification.
- All seven introductory reference suites pass all 23 official cases in Python, JavaScript, and Java within their two-second case limits; starters also compile and parse the samples. Every supplied faulty solution is detected. C++ references/starters are included but compiler verification is skipped because `g++` is unavailable. Private timing records are under `.runtime/content-verification/`; the strengthened tree suite also has a targeted `practice-tree-results.json` report.
- Frontend TypeScript check and production build; production smoke covers all ten challenges, deep-link reloads, real Monaco edits/workers, and local asset delivery.

Managed-provider tests use deterministic fakes and HTTP mock transports; they consume no paid executions and explicitly forbid local subprocesses during managed judging. Provider-free contest tests use the original real executor and forbid constructing Judge0 clients. Screenshots are generated under the ignored `.runtime/` QA directory. Test databases and five extra problem fixtures are temporary; the production catalog has ten challenges (four Easy, three Medium, three Hard). Existing published contests keep their pinned selections.

Actual Render deployment, custom-domain cookies/CORS, and sustained hosted capacity require staging verification. The Docker CLI is installed but its Linux engine was stopped; the new image could not be built/run here. No live deployment is claimed. Provider-free publication/execution has no provider checks. If managed execution is explicitly selected, its separate opt-in compatibility checks still apply. See [the operator guide](hosted-contests.md).
